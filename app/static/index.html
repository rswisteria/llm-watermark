鍵を変えて比較する

      
同じプロンプト・seed で「鍵A / 鍵B / 透かしなし」を順に生成し、各文章を各鍵で判定します。別の鍵で見ると Green 比率が γ に戻り、透かしは検出できません。

      

        γ（ガンマ）と δ（デルタ）とは？
        

          
γ（Green リストの割合、0 < γ < 1、既定 0.25）

          
各ステップで「直前のトークン ID × 鍵」からシードを作り、語彙全体をシャッフルして先頭 γ × 語彙数 個を Green リストにします。γ = 0.25 なら語彙の 25 % が Green です。

          
判定側は「Green トークンの割合が γ より有意に高いか」を z 検定で見ます: z = (g − γT) / √(γ(1−γ)T)。透かしなしの文章や別の鍵で見た文章では Green 比率が γ 付近に戻り、z ≈ 0 になります。

          
γ を小さくすると Green が「珍しい」事象になり、1 トークンあたりの証拠は強くなりますが、モデルが Green を選べる余地が減ります。大きくすると逆です。生成と判定で同じ γ を使う必要があります。

          
δ（Green への logit 加算量、δ ≥ 0、既定 2.0）

          
生成時、Green リストのトークンの logit（確率になる前のスコア）に δ を足してから確率化します。δ が大きいほど Green が選ばれやすくなり、透かしは強く（z が伸びやすく）なりますが、本来の分布から離れるため文章の自然さが下がります。

          
δ = 0 は「透かしなし」です（このタブの 3 レーン目）。次のトークンがほぼ決まっている定型的な文（数え上げなど）では、δ を足しても Green を選ぶ余地がなく z は伸びにくくなります。

          
δ は生成にだけ効き、判定には使いません。判定は「鍵と γ」だけで Green を再計算します。

          
このタブでの使い方

          
鍵A と鍵B で γ・δ を変えて生成し、相互検出マトリクスで「自分の鍵では z が高く、別の鍵では γ 付近に戻る」ことと、δ の大小で z の伸びと文章の質がどう変わるかを見比べてください。生成タブのチップをクリックすると、各ステップで δ が logit にどう足されたかを確認できます。
