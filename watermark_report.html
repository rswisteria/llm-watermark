埋め込み方式と検知結果

Kirchenbauer et al. の token-level watermark の考え方を、 watermark.py と demo.py に実装した結果を、 実際の Qwen3-1.7B の生成・検知ログに基づいて整理したレポートです。

Python 3.10.6 PyTorch 2.13.0+cpu Transformers 5.15.0 Qwen/Qwen3-1.7B CPU / bfloat16

結論

生成時に各トークンの logits を変更し、直前の token ID から決まる 「green list」の候補を選びやすくしています。検知時は同じ tokenizer と hash key で token bigram を再評価し、green token の過剰出現を z-score で判定します。

1. 実装した処理パイプライン

STEP 01
直前 token を読む

input_ids[:, -1] を seed の入力にする。

STEP 02
green list を作る

hash_key × previous_token_id で乱数列を決定し、vocab の 25% を選ぶ。

STEP 03
logits を偏らせる

green token の logits に delta=2.0 を加算して生成確率を上げる。

STEP 04
統計的に検知する

green 数を期待値と比較し、z > 4.0 なら透かしありとする。

実装上、モデルの logits 次元が tokenizer vocab より大きい場合は余剰 ID を -inf にして検知対象外の token を生成しないようにし、小さい場合は 明示的にエラーにしています。

2. 透かしの埋め込み方式

green list の決定

GreenListGenerator.green_list() は、語彙全体の permutation を token ごとに決定的に生成します。乱数 seed は秘密鍵に相当する hash_key と直前 token ID の積です。 

generator.manual_seed(
    config.hash_key * int(previous_token_id)
)
permutation = torch.randperm(
    vocab_size, generator=generator
)
green_ids = permutation[:floor(
    vocab_size * config.gamma
)]

logits へのバイアス

WatermarkLogitsProcessor は Hugging Face の LogitsProcessor として各生成 step に介入し、 green list に含まれる token の logits だけを加算します。softmax 前の 値を変えるため、greedy 固定ではなく sampling と組み合わせて働きます。 

green_ids = self.generator.green_list(
    previous_token_id,
    device=scores.device,
)
result[batch_index, green_ids] += config.delta
重要: この方式は本文の意味を変える変換ではなく、生成時の token 選択確率に 小さな統計的偏りを加える方式です。そのため、短文・低エントロピー文・書き換え後の 文章では検知力が変わります。

3. 検知統計

WatermarkDetector.detect_token_ids() は先頭 token を除いた各 token bigram を評価します。直前 token から再生成した green list に次 token が 含まれる場合を green と数えます。

expected = γT
z = (green − γT) / √(Tγ(1−γ))
p = 0.5 × erfc(z / √2)
判定 = z > z_threshold

今回の既定値

  • gamma = 0.25（各 step の期待 green 率 25%）
  • delta = 2.0
  • hash_key = 15485863
  • z_threshold = 4.0（等号は不成立）

検知時の安全策

生成文字列を decode してから再 token 化した ID と、生成直後の ID が一致しない 場合があります。そのとき demo.py は警告を出し、生成時の token ID で検知します。保存・コピーした本文は、保存後の文字列を再 token 化して検知します。

7. 限界と解釈

  • 検知は z に基づく統計的な証拠であり、文章の作者や意味を保証するものではありません。
  • tokenizer、gamma、hash_key が生成時と異なると、同じ文章でも検知結果は再現できません。
  • 短文ではサンプル数 T が少なく、透かし付きでも閾値未満になることがあります。
  • 言い換え、翻訳、再 token 化、敵対的な編集に対する頑健性はこのデモの保証範囲外です。
  • 生成時の decode と再 token 化が一致しない場合があるため、コードは生成直後の token ID にフォールバックします。
